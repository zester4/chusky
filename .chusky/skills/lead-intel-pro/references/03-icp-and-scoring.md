# ICP and Scoring

## Build or load ICP

Prefer owner memory. If absent, capture a compact ICP once:

```text
- Industries / verticals
- Company size (employees or revenue band)
- Geos
- Triggers (hiring, funding, tech stack, compliance, pain events)
- Target titles / functions
- Hard disqualifiers
- Deal size or segment focus (SMB / mid / enterprise)
```

Save to memory when the owner confirms.

## Scoring model (simple, explainable)

Use a transparent score the owner can argue with. Example (adjust weights to owner):

| Factor | Points (example) |
|--------|------------------|
| Industry match | 0–25 |
| Size match | 0–20 |
| Geo match | 0–10 |
| Title / authority fit | 0–25 |
| Trigger / timing signal | 0–20 |
| **Total** | 0–100 |

Map totals to tiers (example):

- **A:** 75–100  
- **B:** 50–74  
- **C:** 25–49  
- **DQ:** disqualifier hit regardless of score  

Always keep a **one-line rationale** per scored account. Black-box scores erode trust.

## Triggers worth noticing

When Treg or web data shows:

- Recent funding or expansion  
- Hiring in the function you sell to  
- Tech stack that pairs with the product  
- Compliance or migration deadlines  
- Public pain (outages, reviews, job posts describing the problem)  

Note the trigger explicitly — it powers personalization later.

## List hygiene

- Deduplicate by domain + email  
- Prefer work email over personal for B2B unless owner says otherwise  
- One primary contact per account for first touch, plus optional champion  
- Cap list size to what the owner can actually work this week  

## Batch workflow

```text
1. Segment definition
2. Account list (domains/names)
3. Company enrich (bulk within budget)
4. Contact discover + enrich for buying roles
5. Score + tier
6. Hand owner: A-list first, then B
7. Propose sequence only for approved tier
```

Respect Treg budgets: enrich A-priority first when spend is tight.
