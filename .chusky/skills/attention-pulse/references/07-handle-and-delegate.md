# Handle, delegate, or escalate

The pulse exists to **close work**, not to narrate it.

## 1. HANDLE now (Elena / available tools)

Do this when all are true:

- `nextAction` is concrete
- Standing order or policy allows (`prepare` or `act_routine` as appropriate)
- Required tools are in Elena’s allowlist (or already granted this run)
- Action is reversible or routine, or already approved

Examples:

- Update task checkpoint / complete task when objective is done
- Set or adjust reminder for a known follow-up date
- Snooze a loop until a stated wait condition
- Prepare a draft the owner already authorized in substance
- Mark candidate delivered after a real owner-facing digest

After handling: write evidence into the loop/task; **close** only if the objective is fully met.

## 2. DELEGATE (preferred over weak solo attempts)

Hand off when another specialist is the right owner:

| Work | Delegate toward |
|------|-----------------|
| Inbox / comms draft or triage | Ivy or Chusky + workspace-pro |
| Sales / pipeline follow-up | Quinn |
| Customer health / onboarding clients | Aria |
| Research before a decision | Nora |
| Code / repo / preview | Lucas |
| Live call execution | Sofia (approval still applies) |
| Heavy project sequencing | Chusky + project-pro |

Delegation packet must include: objective, done-when, constraints, attention/task ids, and the single next action.

Use durable handoff/task tools — do not rely on chat memory alone.

If you cannot invoke the worker directly from this run, **prepare the packet and nextAction** so Chusky or the next pulse can execute without rediscovery.

## 3. DIGEST (owner only)

Escalate to the owner only when:

- A real choice is required (pricing, hire, legal, strategy)
- Approval gate blocks the action
- Identity/verification or human browser handoff is required
- Authority is missing or conflicting

Digest = short decision request, not a status essay. See `05-digest.md`.

## 4. NO_ACTION

Use when nothing should be done or said:

- No actionable loops/candidates
- Waiting/snoozed and not due
- State unchanged and already notified
- Delivery suppressed (quiet hours / limits / silent)

## Anti-patterns

| Bad | Good |
|-----|------|
| “You have 4 open loops” every hour | Handle 3, digest 1 decision |
| Digest when send is already authorized | Send/prepare, then close or update |
| Vague “follow up sometime” | Concrete nextAction + owner or tool |
| Doing Quinn’s sales job with no context | Delegate with packet |

## Closing rule

```text
handled + objective met     → close loop / complete task
handled + still waiting      → update nextAction once or snooze
delegated                   → loop stays open until specialist/Chusky finishes
digest sent                 → loop stays open until owner decides
```
