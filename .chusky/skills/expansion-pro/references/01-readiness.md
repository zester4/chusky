# Expansion readiness

Use the routed source-of-truth data and attributable account evidence. A
feature request, isolated usage spike, or model inference is a signal to test,
not permission to sell or change a plan.

## Signals

- Core use case adopted
- Positive outcomes acknowledged
- Capacity limits (seats, usage caps) approached
- New team or workflow interest
- Sponsor asks “can it also…”

## Blockers

- Open severity tickets
- Failed payments
- Unclear champion
- Onboarding never reached first win

If blocked, route to retention/onboarding first.

Keep green, yellow, and red health states explicit and record the missing proof
before recommending an expansion motion.
