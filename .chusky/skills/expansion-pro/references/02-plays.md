# Expansion plays

Build the play from verified account context, current health, and an explicit
customer problem. The proposal, commercial terms, and external communication
remain separate steps with their own authority and verification.

1. **Seat expansion** — more users on working workflow
2. **Module attach** — adjacent feature with a named job-to-be-done
3. **Use-case expansion** — new team/process with mini-onboarding
4. **Success plan upsell** — higher support tier when complexity warrants

Each play needs: hypothesis, proof, ask, timeline, owner.

If proof is missing, label the play as a test and define what would validate it;
do not turn an inferred opportunity into a forecast or commitment.
