# Chusky media tool boundary

Chusky media generation is provided by the host agent. App code and app skills
must not create a separate provider integration or ask for a provider API key.

## Native tools

- `CHUCK_GENERATE_IMAGE` accepts `{ prompt, destination?, workspacePath? }` for
  a new image. `destination` defaults to `telegram`; use `daytona` when the
  image is an input to workspace design/code/postprocessing, or `both` when it
  should be saved and shown. With a Daytona destination, the tool uploads the
  real generated bytes and returns the verified workspace path.
- `CHUCK_GENERATE_VIDEO` accepts `{ prompt, destination?, workspacePath? }` and
  starts an asynchronous video workflow. Its default is Telegram delivery;
  `daytona` saves the completed bytes to the verified workspace path, and
  `both` does both. The path becomes usable after the workflow completes and
  reports it, not before.
- Daytona is for deterministic work after a real file exists: composition,
  ffmpeg/Pillow processing, inspection, packaging, and artifact creation.
- Use `CHUCK_ARTIFACT` when a finished website, report, presentation, PDF,
  spreadsheet, image, video, project, or ZIP needs to be registered and
  delivered as an artifact.

## Hard rules

- Never read, create, request, document, or depend on any provider API key
  from an app.
- Never call a provider endpoint or invent historical provider tool calls. They
  are not part of Chusky's runtime tool surface.
- Never invent a returned `file_path`. A path used by Daytona must come from a
  user upload or a verified Daytona filesystem result.
- Source-aware image editing and multi-reference generation are not currently
  exposed by the native Chusky tools. Use a real generated/uploaded file with
  Daytona for deterministic edits, or explain the limitation instead of
  silently substituting a text-only generation.
- For a generated image or video, report the actual destination result. A
  Daytona path may be used by later Daytona tools only after the tool/workflow
  returns and the file is verified.
