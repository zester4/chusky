# Launch plan

Start from Jev's routed launch context and the actual source-of-truth project,
release, and analytics systems. A plan or checklist is not evidence that the
launch is ready; every gate needs an attributable owner and verification.

## Minimum plan fields

- Goal and success metric (e.g. signups, activations, revenue)
- Audience
- Date/time and timezone
- Go/no-go checklist
- Owners per workstream (product, eng, marketing, support, sales)
- Rollback or hold criteria

## Phases

1. Scope freeze
2. Build / QA
3. Asset and messaging lock
4. Soft internal dry run
5. External launch
6. Hypercare window

Create open loops for every incomplete go/no-go item with dueAt.

Keep proposed, approved, live, and rolled-back states separate. If a critical
gate is unknown, the launch remains no-go until it is verified or explicitly
accepted by the decision owner.
