# Use-Case Playbook: Brand Videos, Ads, UGC, and Avatars

All four of these are prompt-engineering and model-selection patterns on top of
the same `POST /api/v1/videos` API described in `api-reference.md` — there is
no separate "ad mode" or "avatar mode" parameter. This file is what to reach
for before writing prompts for these use cases.

## Read this first: what the API can and can't do here

- **Can:** generate short branded/product/commercial-style clips from a prompt,
  optionally anchored to a product photo (`frame_images`) or style/character
  reference (`input_references`); generate model-voiced dialogue with lip-sync
  baked in by models that support it (native `generate_audio`, e.g. Seedance 1.5
  Pro, FLUX 3 Video); produce UGC-style "talking into a handheld camera" aesthetics
  through prompting.
- **Can't:** take a user's own recorded voice/audio track and drive precise
  lip-sync onto a face from it. There is no `audio` / `voice` input parameter in
  this API — dialogue and its lip-sync are generated by the model from your text
  prompt, not from an uploaded audio file. If a user explicitly needs
  "upload my voice recording + a photo → lip-synced talking video," that's a
  different category of tool (audio-driven lipsync/avatar APIs, e.g. Sync,
  HeyGen, InfiniteTalk) — say so plainly rather than approximating it and
  calling it the same thing.
- **Can't guarantee** exact logo/wordmark rendering or brand-perfect color
  matching — text and fine detail rendering varies by model and is not
  pixel-precise. Treat generated on-screen text/logos as a rough pass, not
  production-ready branding, unless the user reviews and accepts the result.

## Brand videos

Goal: a polished clip that represents a product or brand, not a talking person.

- Anchor to real assets with `input_references` (product shots, packaging, brand
  key art) so color palette and product shape carry through, rather than relying
  on the model to invent them from text alone.
- Prompt with concrete visual language: lighting style ("soft studio light" /
  "golden hour"), camera movement ("slow push-in", "orbit around product"),
  material/texture detail, and mood — vague prompts ("a nice ad for my brand")
  produce generic output.
- Good model picks: **Veo 3.1 / Veo 3.1 Fast** for cinematic polish and native
  audio; **MiniMax H3** specifically calls out brand/text rendering and
  instruction-guided edits for commercial creative workflows; **Seedance 2.0** for
  strong character/style consistency across reference material.
- Mention brand-safety limits (above) so the user reviews any generated logo or
  on-screen text before shipping it.

## UGC-style ads

Goal: the "shot on a phone, not a studio" aesthetic that performs well as social
ad creative — imperfection is the point.

- Vertical by default: `aspect_ratio: "9:16"`, short duration (5-10s clips,
  chained/re-generated for hooks + CTA if the user wants a longer spot).
- Prompt for the aesthetic explicitly: "handheld phone camera," "natural window
  light," "casual talking-to-camera energy," "slightly imperfect framing" — a
  model defaults toward polished/cinematic unless told otherwise.
- If starting from a product photo or a creator's photo, use `frame_images`
  (first frame) so the product/person stays visually consistent, then describe
  the motion and delivery in the prompt.
- Good model picks: **Seedance 2.0 Fast** or **Seedance 2.0 Mini** (cheap, fast
  iteration — UGC ad testing is a volume game, generate many variants);
  **Grok Imagine Video** for quick multi-aspect-ratio drafts.
- Set expectations: this produces a UGC-*style* clip, not a real creator's
  video — treat it as a stand-in/prototype unless the user's use case is fine
  with fully synthetic UGC (check platform ad-disclosure policies with them if
  this is going into paid ad placements).

## General ads / commercials

Goal: a scripted, produced-feeling spot (hook, body, CTA) rather than a single
shot.

- Break the ad into beats and generate one clip per beat (e.g. hook / product
  demo / CTA), each a separate job — this API generates single short clips, not
  multi-scene edits, so sequencing/cutting beats together into one video is a
  downstream edit (ffmpeg or a video editor), not something this API does.
- Keep prompts tight per beat: what's on screen, camera move, mood, and any
  on-screen text — one clear idea per clip generates more reliably than a
  multi-beat prompt crammed into one request.
- For variant testing (different hooks, different CTAs), generate several jobs
  in parallel with the same visual setup and only the script/hook line changed —
  cheap models (Seedance Fast/Mini tiers) are the right choice for this kind of
  volume iteration; upgrade to Veo 3.1 / Sora 2 Pro for the final chosen cut.
- Report cost per job back to the user when they're generating many variants —
  it adds up fast at higher resolutions.

## Avatars / talking-heads

Goal: a person or character appears to speak.

- This is prompt-driven dialogue generation, not audio-driven lipsync — see the
  limitation at the top of this file. Write the actual line(s) you want spoken
  into the `prompt` (e.g. `prompt: "A woman in a bright kitchen looks at the
  camera and says, enthusiastically: 'This blender changed my morning
  routine.'"`) and let the model generate both the voice and the lip-sync.
- Use `frame_images` (first frame) with a photo/reference of the character to
  anchor identity/appearance, or `input_references` if you want style guidance
  rather than an exact starting frame.
- Good model picks: **Seedance 1.5 Pro** — explicitly built for simultaneous
  audio+video generation with multi-language lip-sync (English, Mandarin,
  Japanese, Korean, Spanish, and more) and character consistency across shots;
  **FLUX 3 Video** for native audio with lipsync, effects, and ambience.
- If the user wants multiple lines/shots of the *same* character, reuse the same
  reference image across jobs and keep the character description worded
  identically in each prompt to help consistency — full identity-lock across
  separate generation jobs isn't guaranteed.
- Be upfront: voice, accent, and exact pacing are the model's choice unless it
  exposes a passthrough parameter for it (check `allowed_passthrough_parameters`
  via `list_models.py --id <model>`) — this is not voice cloning.
