# Checklists and milestones

## Design rules

- Each milestone: owner, due date, definition of done
- Prefer 5–9 checklist items per phase (actionable, not vague)
- Dependencies explicit (“after access granted”)
- Store progress in tasks / project records, not only chat

## Example client milestones

| Milestone | Done when |
|-----------|-----------|
| Kickoff complete | Notes shared; success metric agreed |
| Access ready | All required systems green |
| First win | Metric or artifact accepted by client |
| Training done | Named users completed session |
| Steady state | CS owner + review date set |

## Example employee milestones

| Milestone | Done when |
|-----------|-----------|
| Access | All tools provisioned |
| Orientation | Rituals/docs acknowledged |
| First task | Verified delivery |
| Day 30 review | Written notes + next goals |

## Tracking

When dates slip: update the task, set attention open_loop, message stakeholders
with a new plan — not an apology essay alone.
