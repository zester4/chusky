## Tool and skill discovery

Use `tools.list()` to discover the Composio and native capabilities available to a project. Use `skills.list()` to inspect the trusted `.chusky/skills` catalog and `skills.files()` or `skills.readFile()` when a skill references supporting scripts, templates, or assets.

```ts
const tools = await chusky.tools.list({ query: "Gmail" });
const skills = await chusky.skills.list();

const run = await chusky.threads.runs(thread.id).create({
  input: "Research the customer and prepare a report.",
  tools: { allow: tools.data.slice(0, 5).map((tool) => tool.slug) },
  skills: skills.data.filter((skill) => skill.name === "research").map((skill) => skill.name),
  wait: false,
  budget: { duration: "3h", maxToolCalls: 60, maxCost: 2 },
});
```

Allow and deny rules are checked before the model sees the catalog and again immediately before execution. A missing connected account is surfaced as a connection requirement; it does not silently grant a credential.

## Generated artifacts and video jobs

Artifacts are verified outputs produced in the Daytona workspace. List them, inspect metadata, and download the bytes through the SDK:

```ts
const artifacts = await chusky.artifacts.list({ type: "report" });
const file = await chusky.artifacts.download(artifacts.data[0].id);
await writeFile("report.pdf", Buffer.from(file.bytes));
```

Video generation is durable and independently cancellable. Submit a job with `videos.create()`, observe it with `videos.get()`, and deliver the completed artifact through the channel or your own storage policy.

## Workers and channels

Workers are durable scheduled routines. `workers.create()` accepts a schedule, task input, budget, and optional channel target. Channels and activity provide the control-plane view needed for dashboards and operational history.

## Attention Pulse and Elena

Attention Pulse is Chusky's proactive operating loop. Elena periodically reviews
bounded, owner-scoped signals from connected apps and durable work, then turns
useful observations into a safe next step instead of producing an unexplained
background run.

The pulse can surface unread communication, upcoming meetings, bills, overdue
work, approvals, failed automations, and artifact or task follow-up. Each update
keeps the distinction between a verified observation, prepared work, an approval
request, and a blocked action. Provider content is treated as untrusted input;
it never grants permission to act.

Configure the pulse through the typed SDK resource:

```ts
const current = await chusky.attentionPulse.get();

const updated = await chusky.attentionPulse.update(
  {
    enabled: true,
    cadence: "hourly",
    authority: "prepare",
    delivery: [
      { channel: "dashboard", enabled: true },
      { channel: "telegram", enabled: true },
    ],
    monitoredDomains: ["communication", "calendar", "work"],
    maxPerDay: 8,
    quietHoursUtc: { start: "22:00", end: "07:00" },
  },
  { idempotencyKey: "pulse-settings-2026-10-07" },
);
```

The available authority levels are `observe`, `prepare`, and
`execute_reversible`. Preparing a draft, reminder, summary, or follow-up can be
automatic when the owner allows it. Financial, destructive,
permission-changing, and other consequential actions still use Chusky's
approval flow. Delivery is explicitly opted in per channel and remains
account-scoped.

## Voice and meetings

Voice calls and Recall meetings are first-class API resources rather than
provider-specific SDK forks. Use `account.voiceOptions()` and
`account.preferences()` for the deployment's Flux/Bland choices, `calls.request()`
for a validated outbound call, and `meetings.prepare()` plus
`meetings.join()` for a meeting representative. See the [calls guide](/docs/calls)
and [meetings guide](/docs/meetings) for provider details and lifecycle handling.
