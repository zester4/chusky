## Install

```bash
npm install @chusky/sdk
```

## Configure the server

```env
CHUSKY_API_KEY=chsk_your_project_key
```

Keep `CHUSKY_API_KEY` in a trusted server environment. Never bundle it into browser JavaScript.
The SDK uses the hosted Chusky API automatically. Set `baseUrl` explicitly only
for staging or self-hosted deployments.

## Create a thread and run the agent

```ts
import { Chusky } from "@chusky/sdk";

const chusky = new Chusky({
  apiKey: process.env.CHUSKY_API_KEY!,
  userId: "customer_123",
});

const thread = await chusky.threads.create({
  metadata: { source: "my-app" },
});

const run = await chusky.threads.runs(thread.id).create({
  input: "Prepare a concise renewal brief.",
});

console.log(run.output);
```

## Stream the response

```ts
for await (const event of chusky.threads.runs(thread.id).stream({
  input: "Prepare a concise renewal brief.",
})) {
  if (event.type === "run.delta") process.stdout.write(event.text);
  if (event.type === "run.approval_required") {
    console.log("Human approval required", event.approval);
  }
}
```

`userId` must be your own application’s authenticated user ID. Chusky uses it to isolate threads, files, memory, approvals, tasks, and connected accounts.

Use a stable identifier from your trusted server-side authentication session.
Do not accept `userId` from a browser request or expose the API key to client
code. New personal keys begin read-only with `threads:read` and `missions:read`;
grant write scopes explicitly when your integration needs to create work.
The thread-creation example below also requires `threads:write`.

## Verify mission access

This read-only call is a useful first integration check. The default key scopes
include `missions:read`:

```ts
const missions = await chusky.missions.list();
console.log(missions.data);
```

Creating a mission starts durable asynchronous work. Configure the worker and
queue for your deployment before creating missions, and send an
`idempotencyKey` in the request options when retrying a create after a timeout.
