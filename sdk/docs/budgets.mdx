---
title: Usage and budget limits
description: Keep model, tool, file, and workflow costs predictable.
---

Budget policies can be set on each run and should also be constrained by the project and user policy in your application.

```ts
const budget = {
  maxToolCalls: 20,
  maxCost: 0.25,
};
```

The server enforces `maxToolCalls` and `maxCost` during the run. A tool-call ceiling produces a resumable boundary with an actionable message; a cost ceiling stops additional tool work. Durable runs also accept `budget.duration` values of `5m`, `30m`, `1h`, `3h`, `6h`, `3d`, or `1w`.

Recommended responses:

- `402 spend_limit` when a budget is exhausted
- `429 rate_limited` when request throughput is exceeded
- `409 policy_violation` when a run requests a disallowed capability

Expose usage through the usage endpoint and include bounded cost metadata in run and webhook records. Never trust a client-provided cost value.

For asynchronous work, combine the budget with `wait: false`; the QStash-backed task resumes from persisted state after a process restart. Treat the returned task as the source of truth for progress and retry state.
