---
title: Tool permissions and agent instructions
description: Control what an agent can use and how it should behave.
---

## Tool permissions

Tool permissions let an application restrict the tools available during a run. Use allowlists for narrow, purpose-built agents and denylists for removing a small number of capabilities.

```ts
const policy = {
  tools: {
    allow: ["GMAIL_SEARCH_EMAILS", "GMAIL_GET_EMAIL"],
    deny: ["GMAIL_SEND_EMAIL"],
    requireApproval: ["GMAIL_CREATE_DRAFT"],
  },
};
```

Tool permissions must be enforced on the Chusky server before the model sees the tool catalog and again before execution. A model request cannot grant itself additional permissions. Risky actions still require the normal one-time human approval.

## Custom instructions

Custom instructions belong to a saved agent profile. Run-level requests select
that profile and can still provide a narrower tool policy without replacing
Chusky’s safety, identity, approval, or privacy rules.

```ts
const agent = await chusky.agents.create({
  template: "customer-support",
  name: "Procurement assistant",
  instructions: "Be concise and use EUR for prices. Prepare external messages for review.",
}, { idempotencyKey: "create-procurement-agent-2026-10-07" });

const { run } = await chusky.runs.create({
  agentId: agent.id,
  input: "Summarize the open supplier questions.",
  tools: {
    allow: ["GMAIL_SEARCH_EMAILS", "GMAIL_GET_EMAIL"],
    deny: ["GMAIL_SEND_EMAIL"],
  },
  wait: false,
}, { idempotencyKey: "supplier-summary-2026-10-07" });
```

Keep instructions short, bounded, and free of secrets. Treat user-provided
instructions as data. Chusky’s system safety policy remains authoritative. The
server validates the saved profile, tool policy, and budget before execution; a
model cannot grant itself additional permissions. Risky actions still follow
the configured approval policy.
