## Supported platforms

The meeting resource supports Recall links for Zoom, Google Meet, Microsoft
Teams, and Webex. Chusky validates the link and platform before sending
anything to Recall. Recall's optional shared-screen understanding is available
only where the deployment and Recall support it.

## Configure the representative

The meeting profile controls how Chusky participates. It contains the display
identity, communication guidance, approved knowledge, meeting tools, account
aliases, and calendar auto-join preference.

```ts
const profile = await chusky.meetings.updateProfile({
  representativeName: "Chusky",
  organizationName: "Acme Motors",
  role: "sales",
  communicationStyle: "Natural, concise, curious, and helpful.",
  approvedKnowledge: "Only use the approved product and pricing facts.",
  allowedComposioTools: ["GOOGLECALENDAR_CREATE_EVENT"],
  autoJoinCalendar: false,
});
```

## Prepare and join

Preparation searches the owner's saved relationship/business context and
returns a private brief. It does not join a meeting. A direct join can receive
that brief as `clientContext`; a calendar-prepared join uses the opaque
preparation ID and never requires the caller to re-send the meeting URL.

```ts
const brief = await chusky.meetings.prepare({
  clientName: "Jordan Lee",
  objective: "Understand whether Acme Motors is a fit for the fleet program.",
});

const meeting = await chusky.meetings.join({
  meetingUrl: "https://meet.google.com/example-room",
  title: "Acme Motors fleet discussion",
  interactionMode: "representative",
  clientName: "Jordan Lee",
  objective: "Understand whether Acme Motors is a fit for the fleet program.",
}, { idempotencyKey: "acme-fleet-meeting-2026-09-15" });
```

`joinAt` schedules the Recall bot when the event is at least ten minutes in the
future. For recurring calendar automation, use the preparation returned by
`meetings.list()` and call `joinPreparation(preparation.id)`. For a calendar
meeting that needs owner-approved relationship context, prepare a brief first
and pass the same reviewed fields when joining:

```ts
const brief = await chusky.meetings.prepare({
  clientName: "Jordan Lee",
  objective: "Review the proposal and agree next steps",
});

await chusky.meetings.joinPreparation(preparation.id, {
  clientName: brief.clientName,
  objective: brief.objective,
});
```

The brief is bounded to normal-sensitivity relationship and business facts. It
does not expose the owner's full chat history or credentials to the meeting.

## Roster, context, and lifecycle

```ts
const snapshot = await chusky.meetings.get(meeting.id);
const context = await chusky.meetings.context(meeting.id, "What approved facts are relevant to pricing?");
await chusky.meetings.leave(meeting.id);
```

The meeting snapshot includes the provider platform, lifecycle status, mission
metadata, and safe retention state. Participant roster and outcomes are
available in `meetings.list()` for the authenticated owner. Meeting context is
available only for an active representative meeting and contains relevant
owner-stored facts, not arbitrary private history.

## Live dashboard synchronization

Use the meeting stream when a dashboard or embedded operator console needs to
stay current without polling. The stream emits an owner- or workspace-scoped
snapshot followed by keepalive events. Reconnect with the last known snapshot
when the transport closes; do not treat a disconnected stream as a completed
meeting.

```ts
const stop = new AbortController();

await chusky.meetings.stream(undefined, (event) => {
  for (const meeting of event.meetings) {
    console.log(meeting.id, meeting.status, meeting.runtimeState);
  }
}, stop.signal);

// Call stop.abort() when the dashboard view unmounts.
```

Meeting preparation records include the calendar attendees when the calendar
provider supplied them. A preparation's attendees are scheduling context, not
authentication. The meeting roster may include a provider-matched email and an
assurance level in an owner-private response; shared workspace projections
omit those identity fields.

For an owner-private meeting, the owner can confirm a present participant only
when the supplied email exactly matches the provider-matched roster email. The
endpoint refuses shared-room meetings, absent participants, duplicate email
matches, and non-matching addresses. Use an idempotency key because the
confirmation changes durable meeting state:

```ts
const confirmed = await chusky.meetings.confirmParticipant(
  meeting.id,
  participant.id,
  "jordan@example.com",
  { idempotencyKey: `confirm-${meeting.id}-${participant.id}` },
);
```

Confirmation is an identity assurance signal, not a grant to unrelated private
data. Sensitive connected-app lookups and external actions continue to use
their normal authorization and approval boundaries.

Use signed Recall webhooks and durable Redis/QStash in production. A successful
join request means Chusky accepted and persisted the meeting lifecycle; use
`get()` or `list()` to observe admission, in-call, ended, and failed states.
